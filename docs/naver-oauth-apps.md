# 네이버 애플리케이션 분리 (#105)

네이버 로그인은 **서버(웹 코드 교환)용 애플리케이션**과 **모바일 앱용 애플리케이션**을 네이버 개발자 센터에서 따로 등록하는 것을 권장한다.

- 네이버 iOS·Android SDK 는 client secret 을 앱 바이너리에 넣는다. 앱에서 추출할 수 있으므로 모바일 앱의 secret 은 공개 값으로 본다.
- 서버의 `OAUTH_NAVER_CLIENT_SECRET` 이 모바일 앱과 같은 값이면, secret 을 꺼낸 누구나 서버와 같은 자격 증명으로 토큰을 만들거나 갱신할 수 있다.
  서버용 애플리케이션을 따로 두면 웹 코드 교환(`POST /api/auth/naver`)의 secret 은 서버(Render 환경변수)에만 남는다.

## 분리 시 주의

현재 `POST /api/auth/naver/native` 는 앱이 보낸 refresh token 을 **서버의 client ID·secret 으로 갱신**해 이 앱에 발급된 토큰인지 확인한다.
이 검증은 서버와 앱이 같은 네이버 애플리케이션일 때만 동작하므로, 애플리케이션을 나누려면 함께 아래 중 하나가 필요하다.

1. 앱도 네이버 인가 코드만 받아 서버 코드 교환(`POST /api/auth/naver`, 서버용 애플리케이션)으로 로그인한다(권장. 앱에서 secret 제거).
2. 서버에 모바일 애플리케이션의 client ID·secret 을 별도 설정으로 두고 native 검증에만 쓴다(모바일 secret 은 여전히 공개 값이라 토큰 대체 공격 방어는 약하다).

어느 쪽이든 분리한 뒤에는 기존에 공개된 secret 을 네이버 개발자 센터에서 재발급한다.
